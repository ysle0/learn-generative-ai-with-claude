## 19.1 Mixture of Experts (MoE) — 모든 뉴런을 쓸 필요는 없다

### 핵심 아이디어

일반적인 Transformer 모델(Dense Model)은 매 토큰마다 모든 파라미터가
연산에 참여합니다. MoE(Mixture of Experts)는 이 접근을 근본적으로 바꿉니다.

> **"모델 전체가 아니라, 각 토큰에 가장 적합한 '전문가'만 활성화하자."**

```
Dense Model: [████████████████████████████]  ← 토큰마다 전체 연산
MoE Model:   [██░░░░░░██░░░░░░░░░░░░░░██]  ← 일부만 활성화
```

### 라우터 메커니즘: 토큰은 어떻게 전문가를 찾아가는가

MoE의 핵심은 **라우터(Router)** 입니다. 작은 신경망으로,
각 토큰의 표현을 입력받아 어떤 전문가에게 보낼지 결정합니다.

```
입력 토큰: "프로그래밍"
           ┌─────────┐
           │  Router  │  ← 가벼운 게이팅 네트워크
           └────┬─────┘
    ┌───────────┼───────────┬───────────┐
    v           v           v           v
┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│Expert 1│ │Expert 2│ │Expert 3│ │Expert 4│
│  0.15  │ │  0.72  │ │  0.08  │ │  0.05  │
└────────┘ └────────┘ └────────┘ └────────┘
  비활성     활성화!     비활성     비활성

→ Top-K (보통 K=2) 전문가만 활성화하고 가중 합산
```

개발자에게 익숙한 비유로, 이것은 **로드 밸런서(Load Balancer)** 와 비슷합니다.
요청의 특성에 따라 적합한 서버로 라우팅하듯, 토큰을 적합한 전문가로 라우팅합니다.

### 실제 MoE 모델들

| 모델 | 총 파라미터 | 활성 파라미터 | 전문가 수 | 비고 |
|------|------------|--------------|----------|------|
| **GPT-4** (추정) | ~1.8T | ~280B | 16개 (추정) | OpenAI 미공개, 유출 정보 기반 |
| **Mixtral 8x7B** | 46.7B | 12.9B | 8개 | Mistral AI, 오픈 가중치 |
| **DeepSeek-V3** | 671B | 37B | 256개 | 학습 비용 약 $5.6M으로 화제 |

### MoE의 장점과 트레이드오프

**장점:** 효율적 스케일링(총 파라미터를 크게 늘려도 추론 비용은 활성 파라미터에 비례),
낮은 추론 비용, 전문가별 특화 가능

**트레이드오프:** 전체 파라미터를 GPU 메모리에 올려야 함,
라우터의 로드 밸런싱 문제, 분산 환경에서의 통신 비용

> **개발자 관점:** MoE가 보편화되면, 같은 API 호출 비용으로 훨씬 더 큰
> 모델을 사용할 수 있게 됩니다.

## 19.2 State Space Models (SSM) — Transformer의 대안이 될 수 있을까?

### Transformer의 근본적 한계

Self-Attention은 시퀀스 길이 n에 대해 **O(n²)** 복잡도를 가집니다.

```
길이(n)  │ Attention (O(n²))  │  SSM (O(n))
─────────┼────────────────────┼──────────────
   1K    │        1M          │      1K
  16K    │      256M          │     16K
 256K    │    65,536M         │    256K
   1M    │ 1,000,000M        │      1M      ← 차이가 극적
```

### Mamba 아키텍처: 선택적 상태 공간 모델

**Mamba**(2023년 Albert Gu, Tri Dao 발표)는 SSM에 **선택적 메커니즘(Selective
Mechanism)** 을 추가하여 입력에 따라 상태 전이를 동적으로 조절합니다.

```
Transformer: 모든 토큰 쌍을 직접 비교 → n×n 연산
  [t1] ←→ [t2] ←→ [t3] ←→ [t4] ←→ [t5]

SSM/Mamba: 상태를 순차적으로 업데이트 → n번 연산
  [t1] → [상태] → [t2] → [상태'] → [t3] → [상태''] → ...
```

핵심 차이점은 Mamba가 **입력에 따라 상태 전이 행렬을 동적으로 변경**한다는 것입니다.
"이 토큰은 중요하니까 상태에 많이 반영하고, 저 토큰은 무시하자"를 선택할 수 있습니다.

### 하이브리드 모델: Transformer + SSM

실제로 가장 유망한 방향은 둘을 **결합**하는 것입니다.

| 모델 | 접근 방식 |
|------|----------|
| **Jamba** (AI21 Labs) | Transformer 레이어와 Mamba 레이어를 교차 배치 |
| **Mamba-2** | Attention과의 이론적 연결(SSD) 발견 |
| **Zamba** (Zyphra) | 공유 Attention + Mamba 블록으로 효율적 하이브리드 |

> **개발자 관점:** SSM이 성숙해지면, "전체 리포지토리를 컨텍스트에 넣고
> 리팩토링해줘"라는 요청이 현실적인 비용으로 가능해집니다.

## 19.3 Long Context — 더 많이, 더 멀리 기억하기

### 컨텍스트 윈도우의 확장 역사

```
2022  │ GPT-3.5          :   4K 토큰   (약 3,000단어)
2023  │ GPT-4            : 128K 토큰   (소설 한 권)
2023  │ Claude 2         : 100K 토큰   (약 75,000단어)
2024  │ Claude 3         : 200K 토큰   (약 150,000단어)
2024  │ Gemini 1.5 Pro   :   1M 토큰   (약 700,000단어)
2025  │ Gemini 2.0       :   2M 토큰   (코드베이스 전체)
      ▼ 미래: 10M+ 토큰?
```

### 롱 컨텍스트를 가능하게 하는 기술들

**RoPE Scaling** — 토큰의 위치 정보를 회전 행렬로 인코딩하는 RoPE의 주파수를
조정하여 학습 시 컨텍스트를 넘어 확장합니다. NTK-aware Scaling, YaRN,
ABF(Llama 3.1에서 사용) 등의 변형이 있습니다.

**ALiBi (Attention with Linear Biases)** — 위치 인코딩을 임베딩에 더하는 대신,
Attention 점수에 거리 기반 편향을 직접 더하여 더 긴 시퀀스에 자연스럽게 일반화됩니다.

**Ring Attention** — 여러 GPU에 걸쳐 시퀀스를 블록으로 나누고,
키-값 텐서를 링 형태로 순환시켜 GPU 수에 비례하여 컨텍스트를 확장합니다.

```
Ring Attention: GPU 간 Key-Value 순환
  GPU 1 ──→ GPU 2 ──→ GPU 3 ──→ GPU 4
    ↑                                │
    └────────────────────────────────┘  KV 텐서가 링 형태로 순환
```

### "건초 더미에서 바늘 찾기" 테스트

**Needle in a Haystack(NIAH)** 테스트는 롱 컨텍스트의 실제 성능을 측정합니다.
매우 긴 텍스트 속에 무관한 사실 하나를 삽입하고 이를 찾아내는지 확인합니다.

```
결과 히트맵 (예시):
              컨텍스트 길이 →
삽입 위치  │  4K    32K   128K   200K    1M
───────────┼──────────────────────────────
  시작     │  ✓     ✓      ✓      ✓      ✓
  중간     │  ✓     ✓      ✓      △      △
  끝       │  ✓     ✓      ✓      ✓      ✓

→ 대부분의 모델이 중간 부분에서 가장 약함 ("Lost in the Middle" 현상)
```

### RAG vs Long Context 논쟁

| 관점 | RAG | Long Context |
|------|-----|-------------|
| **비용** | 필요한 부분만 입력 → 토큰 절약 | 전부 넣으면 비용 증가 |
| **정확도** | 검색 품질에 의존 | 전체 맥락 → 누락 위험 감소 |
| **규모** | 수백만 문서도 검색 가능 | 물리적 한계 존재 |

현실적인 답은 **하이브리드 접근**입니다. RAG로 관련 문서를 검색한 후,
넉넉한 컨텍스트에 여러 문서를 함께 넣어 종합적으로 처리하는 방식이
주류가 되고 있습니다.

## 19.4 Agentic AI — 도구 사용에서 자율 시스템으로

### 진화의 단계

```
Level 0: 단순 질의응답 — 검색 엔진의 대체
Level 1: Copilot — IDE 안에서 자동완성, 한 함수 단위 도움 (GitHub Copilot)
Level 2: Agent — 계획 수립 + 도구 사용 + 자율 실행 (Claude Code, Devin)
Level 3: Autonomous System — 목표만 설정하면 수 시간~수 일 독립 수행 (연구 중)
```

### Computer Use Agent: AI가 컴퓨터를 직접 조작

**Computer Use**는 AI가 마우스 클릭, 키보드 입력, 화면 읽기를 직접 수행합니다.

```
기존: AI → [함수 호출] → DB 조회 → [결과 반환] → AI
Computer Use: AI → [화면 캡처] → "검색창 발견" → [클릭, 타이핑] → [결과 확인]
```

Anthropic의 Claude는 2024년 Computer Use를 공개하며, 웹 브라우저 탐색,
양식 작성, 스프레드시트 편집 등이 가능함을 보여주었습니다.
API가 없는 레거시 시스템과의 통합에서 특히 강력합니다.

### 코딩 에이전트: 자율적으로 코드를 작성하는 AI

```
사용자: "이 프로젝트에 사용자 인증 기능을 추가해줘"

Agent의 행동:
1. 프로젝트 구조 탐색       5. API 엔드포인트 작성
2. 기존 코드 패턴 분석      6. 프론트엔드 구현
3. 구현 계획 수립           7. 테스트 작성 및 실행
4. DB 스키마 수정           8. 실패한 테스트 디버깅 후 최종 확인
```

**Copilot에서 자율 개발자로:**

| 단계 | 인간의 역할 | AI의 역할 | 현재 수준 |
|------|-----------|----------|----------|
| **Copilot** | 설계 + 구현 + 검토 | 자동완성 제안 | 성숙 |
| **Agent** | 설계 + 검토 | 구현 + 테스트 | 빠르게 발전 중 |
| **자율 개발자** | 목표 설정 + 최종 승인 | 설계~배포 전체 | 초기 연구 |

> **개발자 관점:** 에이전트 시대에 개발자의 역할은 "코드를 작성하는 사람"에서
> "AI의 작업을 설계하고 검토하는 사람"으로 이동합니다.

## 19.5 AGI와 ASI — 범용 지능을 향한 논쟁

### AGI란 무엇인가 (그리고 무엇이 아닌가)

**AGI(Artificial General Intelligence)** 는 인간이 수행할 수 있는
거의 모든 지적 작업을 수행할 수 있는 AI를 의미합니다.

```
현재 AI (Narrow AI)              AGI
┌────────────────────┐     ┌────────────────────┐
│ 코딩: ★★★★☆        │     │ 코딩: ★★★★★        │
│ 글쓰기: ★★★★☆      │     │ 글쓰기: ★★★★★      │
│ 물리적 작업: ☆☆☆☆☆  │     │ 물리적 작업: ★★★★☆  │
│ 새로운 과학: ★★☆☆☆  │     │ 새로운 과학: ★★★★★  │
│ 상식 추론: ★★★☆☆    │     │ 상식 추론: ★★★★★    │
└────────────────────┘     └────────────────────┘
  특정 영역에서만 강함         모든 영역에서 인간 수준
```

주의할 점은 AGI에 대한 **합의된 정의가 없다**는 것입니다. "경제적 가치가 있는
모든 작업 수행", "새로운 상황에서의 자율 학습", "의식과 이해의 보유" 등
다양한 기준이 제시되고 있습니다.

**ASI(Artificial Super Intelligence)** 는 모든 영역에서 인간을 크게 초월하는 AI로,
일부 연구자들은 AGI 달성 후 ASI로의 전환이 매우 빠를 수 있다고 경고합니다.

### 주요 기관들의 입장

| 기관 | 입장 | 핵심 주장 |
|------|------|----------|
| **OpenAI** | 낙관적 | AGI 달성이 사명, "인류 전체에 이익" |
| **Anthropic** | 신중한 낙관 | AGI 가능성 인정, 안전성 최우선 |
| **Google DeepMind** | 단계적 접근 | AGI를 레벨로 분류 (Emerging → Superhuman) |
| **Meta AI** | 오픈소스 중심 | 오픈소스가 AGI로 가는 안전한 길 |
| **회의론자들** | 비판적 | LLM은 패턴 매칭일 뿐, 진정한 이해가 없음 |

**낙관론의 근거:** AI 능력의 기대 초월적 향상, 스케일링 법칙의 유효성,
새로운 아키텍처와 학습 기법의 지속 등장

**회의론의 근거:** "통계적 앵무새" 비판, 패턴 매칭 vs 진정한 추론,
학습 데이터의 한계, 물리적 세계 이해 부족

## 19.6 AI Safety & Alignment — 강력한 AI를 안전하게 만들기

### 정렬 문제란 무엇인가

**정렬 문제(Alignment Problem)** 는 AI의 목표와 행동이 인간의 의도, 가치,
기대에 부합하도록 만드는 기술적 과제입니다.

```
잘못 정렬된 AI                 잘 정렬된 AI
├─ 요청하면 무엇이든 수행      ├─ 안전과 윤리를 함께 고려
├─ 해킹 방법 상세 안내         ├─ 위험한 요청 거절 + 합법적 대안 제시
└─ "도움"을 문자적으로 해석     └─ 인간의 가치에 부합하는 방향으로 해석
```

### Constitutional AI: Anthropic의 접근

**Constitutional AI(헌법적 AI)** 는 Anthropic이 개발한 독특한 정렬 방법입니다.

1. AI에게 따라야 할 "헌법" — 원칙들의 집합 — 을 제공
2. AI가 응답을 생성한 후, 헌법에 비추어 스스로 비판하고 수정
3. 이 과정을 통해 RLHF의 인간 의존도를 줄임 (RLAIF: AI 피드백 기반 강화학습)

### 해석 가능성 연구: 모델의 내부를 들여다보기

**해석 가능성(Interpretability)** 연구는 신경망 내부에서 각 뉴런이나 회로가
어떤 개념을 표현하는지를 밝히려는 시도입니다.

- **Mechanistic Interpretability**: 개별 뉴런과 회로 분석으로 내부 메커니즘 규명
- **Sparse Autoencoders**: 모델 활성화를 해석 가능한 특성(feature)으로 분해
- **Representation Engineering**: 내부 표현을 직접 조작하여 행동 제어

Anthropic은 2024년 Claude 내부에서 수백만 개의 해석 가능한 특성을 발견했습니다.
"거짓말"이나 "위험한 행동" 관련 특성을 식별하고, 인위적으로 활성화하거나
억제할 수 있음을 보여주었습니다.

### 책임 있는 스케일링 정책

Anthropic의 **Responsible Scaling Policy(RSP)** 는 AI 모델의 능력이
특정 임계점을 넘기 전에 안전 조치가 마련되어 있는지 확인하는 프레임워크입니다.

```
ASL-1: 위험 없음 (체스 AI 수준) → 특별한 안전 조치 불필요
ASL-2: 현재 대부분의 LLM → 기본 안전 학습, 유해 콘텐츠 필터링
ASL-3: 위험 정보에 의미있는 향상 제공 가능 → 강화 보안, 엄격 평가
ASL-4+: 미래의 더 강력한 모델 → 사전 안전 기준 충족 시에만 배포
```

## 19.7 AI 규제와 거버넌스 — 전 세계의 대응

### EU AI Act: 위험 기반 규제의 선두주자

유럽연합의 **EU AI Act**는 세계 최초의 포괄적 AI 규제법입니다(2024년 발효).

```
EU AI Act의 위험 기반 분류

  금지: 사회적 점수 시스템, 실시간 원격 생체 인식, 취약계층 대상 조작적 AI
  고위험: 채용, 신용 평가, 교육, 법 집행 → 적합성 평가 + 투명성 의무
  제한적 위험: 챗봇(AI 고지 의무), 딥페이크(AI 생성 표시)
  최소 위험: 스팸 필터, 게임 AI 등 → 규제 없음
```

**범용 AI 모델(GPAI) 추가 규정:** 기술 문서 작성, 저작권 준수 의무.
시스템 리스크가 있는 GPAI(학습에 10^25 FLOP 이상)에는 모델 평가,
적대적 테스트(red teaming), 사이버 보안 조치가 추가됩니다.

### 미국의 AI 행정명령

2023년 10월 바이든 대통령의 **AI 행정명령(Executive Order on AI)** 은
안전 테스트 결과 보고 의무, AI 콘텐츠 워터마킹 표준, 프라이버시 보호 강화 등을
제시했습니다. 다만 법률이 아닌 행정명령이므로, 행정부 교체에 따라 변경될 수 있습니다.

### 주요 국가별 접근

| 국가/지역 | 접근 방식 | 특징 |
|-----------|----------|------|
| **한국** | AI 기본법 추진 | 혁신 촉진과 위험 관리 균형, AI 윤리 기준 마련 |
| **일본** | 히로시마 AI 프로세스 | G7 기반 국제 협력, 소프트로 접근 |
| **중국** | 분야별 개별 규제 | 생성형 AI 서비스 관리법, 알고리즘 추천 관리법 |
| **영국** | Pro-innovation | 기존 규제 기관에 AI 감독 역할 부여 |

> **개발자 관점:** AI 서비스를 개발할 때 대상 시장의 규제를 반드시 확인하세요.
> 특히 EU 시장 대상이면 EU AI Act 준수가 필수이며,
> 고위험 카테고리 해당 여부를 사전에 평가해야 합니다.

## 19.8 오픈소스 AI의 부상 — 개방형 생태계의 성장

### 주요 오픈 모델들

```
Meta (LLaMA 시리즈)
├── LLaMA 2 (2023) — 오픈 AI 생태계의 촉발점
├── LLaMA 3 (2024) — 405B, GPT-4에 근접
└── LLaMA 3.1/3.2 — 다국어, 멀티모달 확장

Mistral AI
├── Mistral 7B (2023) — 작지만 강력
├── Mixtral 8x7B (2023) — 오픈 MoE의 시작
└── Mistral Large (2024) — 상용 수준

DeepSeek
├── DeepSeek-V3 (2024) — 671B, 학습 비용 $5.6M
└── DeepSeek-R1 (2025) — 추론 특화, o1 수준

Alibaba (Qwen 시리즈)
├── Qwen2 (2024) — 다국어 강점
└── Qwen2.5 (2024) — 코딩, 수학 상위권
```

### "오픈 가중치" vs "진정한 오픈소스" 논쟁

대부분의 "오픈소스" AI 모델은 엄밀히 **오픈 가중치(Open Weights)** 모델입니다.

| 구성요소 | 오픈 가중치 | 진정한 오픈소스 |
|---------|-----------|---------------|
| 모델 가중치 | O | O |
| 추론 코드 | O | O |
| 학습 코드 | 부분 공개 | O |
| 학습 데이터 | X | O |
| 상업적 사용 | 라이선스별 상이 | 자유 |

OSI(Open Source Initiative)는 2024년 Open Source AI의 정의를 공식화하며,
가중치, 학습 코드, 데이터 정보의 충분한 공개를 요구했습니다.

### 오픈소스 AI가 가져오는 변화

**긍정적 효과:** 기술 민주화(중소기업과 개인 개발자도 접근), 도메인별 커스터마이징,
모델 투명성, API 비용 회피, 폐쇄형 모델과의 경쟁으로 생태계 발전 가속

**우려 사항:** 안전 장치 제거(jailbreak)의 용이성, 악의적 파인튜닝 위험,
오픈 모델 오용에 대한 법적 책임의 불명확성

## 19.9 종합: 개발자가 주목해야 할 핵심 흐름

### 단기 (1-2년) — 확실한 변화

1. **MoE 아키텍처의 보편화**: 새 대형 모델 대부분이 MoE 기반
2. **코딩 에이전트의 일상화**: AI 코딩 에이전트가 표준 개발 도구로 자리매김
3. **롱 컨텍스트 + RAG 하이브리드**: 두 기술의 조합이 표준 아키텍처로 정착
4. **오픈소스 모델과 폐쇄형 모델의 격차**: 3-6개월로 축소
5. **추론 비용의 급격한 하락**: 같은 성능 기준 비용이 매년 10배 이상 감소

### 중기 (3-5년) — 높은 가능성

1. **하이브리드 아키텍처**: Transformer + SSM + MoE 결합의 새 표준
2. **자율 에이전트의 성숙**: 수 시간 단위 자율 작업이 안정적으로 가능
3. **멀티모달의 완성**: 텍스트, 이미지, 오디오, 비디오, 코드의 완전 통합
4. **AI 규제의 구체화**: 국제적 규제 프레임워크가 실질적으로 작동
5. **해석 가능성 도구의 실용화**: 모델 의사결정 감사(audit)가 가능

### 장기 (5-10년) — 불확실하지만 중요

1. **AGI 수준 AI의 등장 여부**: 가장 큰 불확실성이자 가장 큰 영향
2. **AI-인간 협업의 새 패러다임**: 소프트웨어 개발 방식의 근본적 변화
3. **사회적 적응**: 교육, 직업, 법률 체계의 AI 시대 대응
