# Chapter 07. LLM은 어떻게 학습되는가

> LLM은 하루아침에 똑똑해지지 않는다. 수조 개의 텍스트를 읽고, 인간의 피드백을 받고, 안전성을 갖추기까지 — 그 파이프라인을 해부한다.

## 3단계 학습 파이프라인 개요

LLM이 "쓸 만한 AI 어시스턴트"가 되기까지는 세 단계를 거친다.

```
┌─────────────────────────────────────────────────────────────────┐
│                LLM 학습 파이프라인 (Training Pipeline)            │
│                                                                 │
│  ┌──────────────┐   ┌──────────────┐   ┌────────────────────┐  │
│  │ 1. Pre-train │──>│ 2. SFT       │──>│ 3. Alignment       │  │
│  │ (사전학습)    │   │ (지도 미세조정)│   │ (정렬)             │  │
│  └──────┬───────┘   └──────┬───────┘   └──────────┬─────────┘  │
│         │                  │                       │            │
│  수조 토큰 텍스트    지시-응답 쌍 수만개     인간 선호도 데이터   │
│         ▼                  ▼                       ▼            │
│  "다음 단어를         "지시를 따르는         "안전하고 유용한     │
│   예측하는 모델"       도우미 모델"            정렬된 모델"       │
│                                                                 │
│  비용: ~$100M+        ~$1-10M               ~$1-10M            │
│  기간: 수주~수개월     수일~수주              수일~수주           │
└─────────────────────────────────────────────────────────────────┘
```

## 1단계: 사전학습 (Pre-training)

### 사전학습이란

사전학습은 LLM 학습에서 가장 비용이 크고, 모델의 "기초 체력"을 결정하는 단계다. 모델은 인터넷에서 수집한 방대한 텍스트를 읽으며 언어의 구조, 세계 지식, 추론 패턴을 습득한다. 아이가 수년간 책을 읽으며 세상을 배우는 것과 비슷하다.

### 학습 데이터셋 (Training Dataset)

GPT-4 급 모델은 수조(Trillion) 개의 토큰을 학습한다.

| 데이터 소스 | 설명 | 특징 |
|-------------|------|------|
| **Common Crawl** | 웹 크롤링 인터넷 텍스트 | 최대 규모, 노이즈 많음 |
| **Wikipedia** | 위키피디아 전체 텍스트 | 고품질 백과사전 지식 |
| **Books** | 디지털화된 도서 | 깊이 있는 장문 텍스트 |
| **Code** | GitHub 소스 코드 | 프로그래밍 능력의 원천 |
| **학술 논문** | ArXiv, PubMed 등 | 전문 지식과 논리적 추론 |
| **대화 데이터** | Reddit, StackOverflow | 대화 패턴과 Q&A 형식 |

이런 소스들의 혼합 비율은 모델 성능에 큰 영향을 미치며 각 연구소의 핵심 노하우다.

### 학습 목표: 인과적 언어 모델링 (Causal Language Modeling)

디코더 전용(Decoder-Only) 모델의 학습 목표는 극도로 단순하다: **주어진 문맥을 보고 다음 토큰을 예측하라.**

```
"서울"   → "의"      (예측 확률 분포에서 학습)
"서울의" → "수도"    (예측 확률 분포에서 학습)
"서울의 수도는" → "한국" (예측 확률 분포에서 학습)

손실 함수: L = -1/T * Sigma log P(x_t | x_1, ..., x_{t-1}; theta)
```

이 단순한 목표가 왜 "지능"을 만드는가? "대한민국의 수도는 ___이다"를 예측하려면 지리 지식이 필요하고, "x > 0이고 y < 0이면 x*y는 ___이다"를 예측하려면 수학 추론이 필요하다. 수조 개의 예측을 반복하며 모델은 세상의 지식을 파라미터에 압축한다.

### 분산 학습 (Distributed Training)

GPT-4 급 모델은 수천~수만 개의 GPU가 필요하다. 세 가지 병렬화 기법을 조합하여 이를 해결한다.

**데이터 병렬화 (Data Parallelism)**: 동일한 모델 복사본을 여러 GPU에 배치하고 데이터를 분할하여 독립 계산 후 그래디언트를 합산(All-Reduce)한다. 가장 기본적이지만, 모델이 단일 GPU 메모리를 초과하면 불가능하다.

**텐서 병렬화 (Tensor Parallelism)**: 하나의 레이어를 여러 GPU에 분할한다. 큰 행렬 곱셈을 나누어 계산한다. Megatron-LM에서 제안되었으며, 고속 인터커넥트(NVLink)가 필수다.

**파이프라인 병렬화 (Pipeline Parallelism)**: 모델의 레이어들을 여러 GPU에 순차 배치한다. 96개 레이어 모델을 4 GPU에 나누면 각각 24개 레이어를 담당한다. "파이프라인 버블"을 줄이기 위해 마이크로 배칭을 사용한다.

```
실제 대규모 학습은 3D 병렬화를 사용한다:

GPT-3 학습 예시 (NVIDIA):
  텐서 병렬화:     8-way
  파이프라인 병렬화: 8-way
  데이터 병렬화:    64-way
  총 GPU:          8 x 8 x 64 = 4,096개
```

여기에 ZeRO(Zero Redundancy Optimizer), Gradient Checkpointing, Mixed Precision Training(BF16) 등 메모리 최적화 기법이 추가된다.

## 2단계: 지도 미세조정 (Supervised Fine-Tuning, SFT)

### SFT란 무엇인가

사전학습된 모델은 놀라운 언어 능력이 있지만 아직 "도우미"는 아니다. "서울의 인구는?"이라고 물으면 답변 대신 "서울의 면적은? 서울의 위치는?"처럼 관련 질문을 이어 생성할 수 있다. 학습 목표가 "다음 토큰 예측"이지 "질문 답변"이 아니기 때문이다.

SFT는 이 원시 LLM을 **대화형 도우미**로 변환한다. 고품질 (지시, 응답) 쌍으로 지시를 따르는 법을 학습시킨다.

### 지시 따르기 데이터셋 (Instruction Following Dataset)

```json
{
  "instruction": "Python으로 피보나치 수열의 n번째 항을 구하는 함수를 작성해주세요.",
  "output": "def fibonacci(n):\n    a, b = 0, 1\n    for _ in range(n):\n        a, b = b, a + b\n    return a"
}
```

데이터 출처는 두 가지다. **인간 직접 작성**(고비용, 고품질)과 **AI 지원 생성**(기존 LLM으로 생성 후 인간 검수). OpenAssistant(160K), FLAN Collection(수백만), ShareGPT(70K) 등이 대표적이다.

### 원시 LLM이 도우미가 되는 과정

```
[SFT 전] 사용자: "이메일 작성을 도와줘."
         모델:  "이메일 작성을 도와줘라고 부탁하는 것은 일상적인..." (백과사전 서술)

[SFT 후] 사용자: "이메일 작성을 도와줘."
         모델:  "네! 받는 사람, 목적, 원하시는 톤을 알려주세요."
```

SFT는 기존 지식을 파괴하지 않으면서 "응답 형식"을 가르친다. 수만~수십만 개의 데이터로 극적인 변화가 가능한 이유는 사전학습에서 이미 지식과 능력을 갖추었고, SFT는 그것을 올바르게 출력하는 법만 가르치기 때문이다.

## 3단계: 정렬 (Alignment)

### 왜 정렬이 필요한가

SFT만으로는 유해한 응답 생성, 과도한 자신감(환각), 비윤리적 요청에 순응하는 문제가 남는다. 정렬은 모델을 **안전하고, 유용하며, 정직한** 방향으로 조정하는 것이다.

### RLHF (Reinforcement Learning from Human Feedback)

OpenAI의 InstructGPT(2022)에서 대중화된 정렬 기법이다. 세 단계로 구성된다.

**Step 1: 인간 선호도 수집** -- 동일 프롬프트에 대한 여러 응답을 인간이 비교 평가한다.

```
프롬프트: "양자 컴퓨팅을 5살 아이에게 설명해줘"
응답 A: "큐비트를 사용하여 중첩과 얽힘..." (너무 어려움)
응답 B: "일반 컴퓨터는 동전의 앞뒤만 보지만, 양자 컴퓨터는 돌아가는
         동전도 볼 수 있는 마법 컴퓨터야!" (적절)
인간 평가: B > A
```

**Step 2: 보상 모델 학습** -- 선호도 데이터로 "응답이 얼마나 좋은가"를 점수로 출력하는 보상 모델(Reward Model)을 학습한다.

```
Loss = -log(sigmoid(r(x, y_win) - r(x, y_lose)))
→ 선호 응답에 더 높은 점수를 부여하도록 학습
```

**Step 3: PPO로 정책 최적화** -- 보상 모델을 사용하여 LLM을 강화학습으로 최적화한다.

```
최적화 목표: maximize E[r(x, y)] - beta * KL(pi_theta || pi_ref)

1. LLM이 응답 생성 → 2. 보상 모델이 점수 부여
→ 3. PPO로 파라미터 업데이트 → 4. 반복
```

KL 페널티는 모델이 SFT에서 크게 벗어나지 않도록 제약한다. 이것 없이 보상만 최대화하면 보상 모델을 "속이는" Reward Hacking이 발생한다.

**RLHF의 한계**: 보상 모델이 불완전할 수 있고, PPO가 불안정하며, 모델 3개(SFT, 보상, 정책)가 필요하여 파이프라인이 복잡하다.

### DPO (Direct Preference Optimization) - RLHF의 간소화된 대안

2023년 발표된 DPO는 **보상 모델 없이 선호도 데이터에서 직접 정책을 최적화**한다.

```
RLHF: 선호도 데이터 → 보상 모델 학습 → PPO 최적화 (3단계)
DPO:  선호도 데이터 → 직접 정책 최적화 (1단계)

L_DPO = -E[log sigma(beta * (log pi_theta(y_w|x)/pi_ref(y_w|x)
                            - log pi_theta(y_l|x)/pi_ref(y_l|x)))]
```

DPO의 장점: 보상 모델 불필요, 안정적 학습, 간단한 구현(일반 지도학습처럼), 메모리 효율적(모델 2개). LLaMA 2, Zephyr 등에서 RLHF와 동등하거나 더 나은 성능을 보였다.

### Constitutional AI - Anthropic의 접근법

Claude를 차별화하는 핵심 기술이 **Constitutional AI(CAI)**다. 기존 RLHF는 인간 어노테이터에 전적으로 의존하는데, 어노테이터마다 기준이 다르고, 확장에 한계가 있다.

CAI는 명시적 원칙(Constitution)을 모델에 제시하고 **모델 스스로 응답을 평가/개선**하게 한다.

```
[1단계: 자기 비평과 수정 (Self-Critique and Revision)]
  사용자 요청 → 초기 응답 생성 → 원칙에 비추어 자기 비평
  → 위반 시 수정 버전 생성 → 수정된 응답으로 SFT 데이터 구축

원칙 예시:
- "유해하거나 비윤리적 내용을 포함하지 않는지 확인하라"
- "위험한 요청은 왜 도울 수 없는지 정중히 설명하라"

[2단계: RLAIF (RL from AI Feedback)]
  수정 전/후 응답 쌍 → AI 피드백 기반 보상 모델 → 강화학습
```

Constitutional AI 덕분에 Claude는 **일관된 원칙**에 따라 행동하고, 인간 평가 없이도 **확장 가능한 안전성**을 갖추며, 위험한 요청을 **투명하게 거절**하면서 대안을 제시한다. "도움이 되고, 무해하며, 정직한(Helpful, Harmless, Honest: HHH)" Anthropic의 철학이 반영된 결과다.

## 데이터 큐레이션 (Data Curation)

### 데이터 품질이 모든 것을 결정한다

"Garbage In, Garbage Out" -- 아무리 좋은 아키텍처와 컴퓨트도 나쁜 데이터를 이기지 못한다.

### 중복 제거 (Deduplication)

웹 데이터에는 동일 뉴스가 수백 사이트에 복사되는 등 엄청난 중복이 있다.

- **정확 중복 제거 (Exact Dedup)**: 해시 기반 동일 문서 제거
- **근사 중복 제거 (Near Dedup)**: MinHash, SimHash로 유사 문서 제거
- **n-gram 중복 제거**: 반복되는 패턴 제거

중복 제거만으로도 성능이 유의미하게 향상된다. 중복은 특정 패턴의 과도한 암기를 유발하여 일반화 능력을 떨어뜨린다.

### 필터링 (Filtering)

- **언어 필터링**: 목표 언어가 아닌 텍스트 제거 (fastText 언어 분류기)
- **품질 필터링**: Perplexity 기반 필터, 휴리스틱 필터(특수문자 비율, 반복률 등)
- **개인정보 제거**: 이메일, 전화번호 등 PII 제거

### 유해 콘텐츠 제거 (Toxicity Removal)

- **분류기 기반**: Perspective API 등으로 유해도 점수를 매겨 임계값 이상 제거
- **키워드 기반**: 알려진 유해 단어/구문 목록으로 필터링
- **주의**: 지나친 필터링은 소수자 관련 데이터를 과도 제거하여 편향을 유발한다

### 데이터 혼합 비율 (Data Mixing)

```
웹 텍스트 (Common Crawl)   60%  ████████████████████████
도서 (Books)              15%  ██████
코드 (Code)               10%  ████
위키피디아 (Wikipedia)      5%  ██
학술 논문 (Academic)        5%  ██
대화 데이터 (Conversation)   5%  ██
```

코드 비율을 높이면 코딩 능력이 올라가지만 다른 능력이 저하될 수 있다. 항상 트레이드오프가 존재한다.

| GPT-3 (2020) | 175B | ~$5M | ~3,640 PFLOP/s-days |
| LLaMA 2 70B (2023) | 70B | ~$2-3M | 1,720,320 GPU-hours (A100) |
| GPT-4 (2023) | 비공개 (추정 ~1.8T MoE) | ~$60-100M+ | 수만 A100, 수개월 |
| LLaMA 3 405B (2024) | 405B | ~$60-100M+ | 30,840,000 GPU-hours (H100) |

> 위 비용은 공개 정보와 업계 추정치 기반이며 실제와 다를 수 있다.

### 비용 구성 상세

```
GPT-4 급 모델 학습 추정 총비용: ~$100M

GPU 임대/감가 비용  (H100 x 25,000 x 90일)     ~70-80%
전력 비용          (25,000 GPU x 700W x 90일)   ~10-15%
인프라/네트워킹    (InfiniBand, 스토리지 등)     ~5-10%
인건비            (연구원, 엔지니어)             ~3-5%
데이터 수집/처리                                 ~2-3%
```

### FLOP으로 보는 학습 연산량

```
Training FLOP ≈ 6 * N * D
(N: 파라미터 수, D: 학습 토큰 수, 6 = 순전파 2 + 역전파 4)

GPT-3: 6 * 175B * 300B = 3.15 x 10^23 FLOP
LLaMA 2 70B: 6 * 70B * 2T = 8.4 x 10^23 FLOP
```

## Chinchilla 스케일링 (Chinchilla Scaling)

GPT-3 이후 "모델을 크게 만들면 좋아진다"가 통념이었다. 2022년 DeepMind의 **Chinchilla 논문**은 이를 뒤집었다.

### 핵심 발견

동일 컴퓨트 예산에서 모델 크기(N)와 데이터 양(D)의 최적 비율을 조사한 결과:

```
최적 학습 토큰 수 D ≈ 20 * N (파라미터 수)

  1B 파라미터 → 약 20B 토큰
 70B 파라미터 → 약 1.4T 토큰
200B 파라미터 → 약 4T 토큰
```

| 기존 접근 (GPT-3 시대) | Chinchilla 이후 |
|------------------------|-----------------|
| 모델 크기에 집중 | 데이터 양도 동등하게 중요 |
| 175B 파라미터 + 300B 토큰 | 70B + 1.4T 토큰이 더 효율적 |
| "파라미터 수 = 실력" | "최적 비율이 중요" |

Chinchilla(70B, 1.4T 토큰)는 Gopher(280B, 300B 토큰)보다 4배 작으면서 거의 모든 벤치마크에서 더 좋았다. 이후 LLaMA 시리즈는 이 교훈을 반영했고, LLaMA 3는 405B에 15T+ 토큰을 사용하는 "과도학습(Over-training)" 전략까지 채택했다.

## LoRA와 파라미터 효율적 미세조정 (PEFT)

### 문제: 전체 파라미터 미세조정은 너무 비싸다

수천억 파라미터를 모두 학습하려면 거대한 GPU 클러스터, 수백 GB 스토리지가 필요하다. 여러 용도의 모델을 유지하면 비용이 기하급수적으로 증가한다.

### LoRA (Low-Rank Adaptation)

2021년 Microsoft가 발표한 LoRA는 가장 널리 사용되는 PEFT 기법이다. 핵심 아이디어:

> **가중치 업데이트 행렬(Delta W)은 저랭크(Low-Rank)이므로 두 개의 작은 행렬로 분해할 수 있다.**

```
기존: W' = W + DeltaW          (DeltaW는 d x d 크기)
LoRA: W' = W + B x A           (B: d x r, A: r x d, r << d)

예시 (d=4096, r=16):
  원래 파라미터: 4096 x 4096 = 16,777,216
  LoRA 파라미터: 4096 x 16 x 2 = 131,072 (약 0.78%, 128배 절감!)

┌──────────────────────────────────────────┐
│  입력 x ──────────┐                      │
│       │            │                      │
│       ▼            ▼                      │
│   ┌────────┐  ┌─────────┐                │
│   │ W (동결)│  │LoRA: B*A│                │
│   │ d x d  │  │ (학습)   │                │
│   └───┬────┘  └────┬────┘                │
│       └──────+─────┘                      │
│           h = Wx + BAx                    │
└──────────────────────────────────────────┘
```

**LoRA의 장점**: 메모리 대폭 절감, 빠른 학습, 어댑터가 수 MB 수준이라 용도별 다수 유지 가능, 교체도 간단하다.

### QLoRA - 극단적 효율화

기본 모델을 4비트 양자화한 상태에서 LoRA를 적용하는 기법이다.

```
65B 모델 전체 미세조정:  ~780 GB (GPU 메모리)
65B 모델 LoRA:          ~200 GB
65B 모델 QLoRA (4-bit): ~33 GB  ← 단일 GPU로 가능!
```

### 기타 PEFT 기법들

| 기법 | 핵심 아이디어 | 학습 파라미터 비율 |
|------|-------------|-------------------|
| **LoRA** | 가중치 업데이트를 저랭크 행렬 분해 | ~0.1-1% |
| **QLoRA** | 4-bit 양자화 + LoRA | ~0.1-1% |
| **Prefix Tuning** | 입력 앞에 학습 가능한 가상 토큰 추가 | ~0.1% |
| **Prompt Tuning** | 소프트 프롬프트(연속 벡터) 학습 | ~0.01% |
| **Adapter Layers** | 트랜스포머 레이어 사이에 작은 어댑터 삽입 | ~1-5% |

## 파국적 망각 (Catastrophic Forgetting)

### 문제 정의

**파국적 망각(Catastrophic Forgetting)**은 새로운 작업 학습 시 이전 지식을 급격히 잃는 현상이다.

```
[미세조정 전]
"프랑스의 수도는?" → "파리입니다" (정상)
"Python list 정렬?" → "sorted()를 사용합니다" (정상)

[의료 도메인 미세조정 후]
"당뇨병 증상은?"    → "다음, 다뇨, 다식" (새 지식 OK)
"프랑스의 수도는?" → "파리... 증후군은 여행자가..." (기존 지식 손상!)
```

신경망 파라미터는 모든 작업에 공유되므로, 새 데이터 학습 시 기존 최적 가중치가 "덮어써진다."

### 완화 전략

**1. 학습률 조절**: 미세조정 시 사전학습보다 10배 이상 작은 학습률(~1e-5)을 사용한다.

**2. 데이터 혼합 (Replay)**: 미세조정 데이터에 사전학습 데이터 일부(~20%)를 섞어 기존 지식을 유지한다.

**3. LoRA/PEFT**: 원래 가중치를 동결하고 소규모 파라미터만 학습하므로 구조적으로 망각을 방지한다.

**4. 정규화 (EWC 등)**: 이전 작업에 중요한 파라미터가 크게 변하지 않도록 제약을 건다.

```
EWC: L_total = L_new + lambda * Sigma(F_i * (theta_i - theta*_i)^2)
(F_i: Fisher 정보 행렬 = 파라미터 중요도)
```

**5. 모델 병합**: 다른 작업으로 미세조정된 모델들의 가중치를 산술적으로 병합한다(Linear Merging, TIES, DARE).

## 학습 파이프라인 전체 정리

```
[데이터 수집] Common Crawl, Wikipedia, Books, Code
      ▼
[데이터 큐레이션] 중복 제거 → 필터링 → 유해 콘텐츠 제거 → 혼합 비율 결정
      ▼
[1단계: Pre-training] 다음 토큰 예측 | 3D 병렬화 | ~$100M+ | 수개월
      ▼
 ─── 원시 LLM (Base Model) ───
      ▼
[2단계: SFT] 지시-응답 학습 | ~$1-10M | 수일~수주
      ▼
 ─── 도우미 모델 (Chat Model) ───
      ▼
[3단계: Alignment] RLHF / DPO / Constitutional AI | ~$1-10M | 수일~수주
      ▼
 ─── 정렬된 모델 (Aligned Model) ───
      ▼
[선택: 도메인 미세조정] LoRA / QLoRA / PEFT + 파국적 망각 완화
      ▼
 ─── 최종 배포 모델 ───
```

## 핵심 요약

| 주제 | 핵심 내용 |
|------|----------|
| **Pre-training** | 수조 토큰으로 다음 토큰 예측 학습. 전체 비용의 대부분 |
| **SFT** | 수만~수십만 지시-응답 쌍으로 도우미 변환 |
| **RLHF** | 인간 선호도 → 보상 모델 → PPO. 강력하지만 복잡 |
| **DPO** | 보상 모델 없이 직접 최적화. RLHF의 간소화 대안 |
| **Constitutional AI** | 원칙 기반 자기 비평으로 Claude의 안전성 확보 |
| **Data Curation** | 중복 제거, 필터링, 유해 콘텐츠 제거. 데이터 품질 = 모델 품질 |
| **Compute Budget** | GPT-4 급 ~$100M+. GPU 비용이 대부분 |
| **Chinchilla** | 최적 데이터:파라미터 비율은 약 20:1 |
| **LoRA/PEFT** | 전체의 0.1-1%만 학습하여 효율적 미세조정 |
| **Catastrophic Forgetting** | 새 학습 시 기존 지식 상실. LoRA, 데이터 혼합 등으로 완화 |
