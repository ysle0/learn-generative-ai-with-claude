# Chapter 07. LLM은 어떻게 학습되는가

> LLM은 하루아침에 똑똑해지지 않는다. 수조 개의 텍스트를 읽고, 인간의 피드백을 받고, 안전성을 갖추기까지 — 그 파이프라인을 해부한다.

## 키워드 요약

| 키워드 | 설명 |
|--------|------|
| **Pre-training** | 대규모 텍스트 데이터로 일반 지식을 습득하는 첫 번째 단계 |
| **Fine-tuning** | 특정 작업이나 도메인에 맞게 모델을 조정하는 과정 |

| **PPO (Proximal Policy Optimization)** | RLHF에서 정책을 최적화하는 강화학습 알고리즘 |
| **Reward Model** | 인간 선호도를 학습한 보상 모델 |
| **Data Curation** | 학습 데이터의 수집, 정제, 필터링 과정 |
| **Compute Budget** | 모델 학습에 필요한 연산 자원과 비용 |
| **Chinchilla Scaling** | 모델 크기와 데이터 양의 최적 비율을 제시한 연구 |
| **LoRA (Low-Rank Adaptation)** | 적은 파라미터만 학습하는 효율적 미세조정 기법 |
| **PEFT (Parameter-Efficient Fine-Tuning)** | 전체 파라미터 대신 일부만 조정하는 미세조정 방법론 |

## 3단계 학습 파이프라인 개요

LLM이 "쓸 만한 AI 어시스턴트"가 되기까지는 세 단계의 학습 파이프라인을 거친다. 각 단계는 서로 다른 목적, 데이터, 비용 구조를 가진다.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    LLM 학습 파이프라인 (Training Pipeline)                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌───────────────┐    ┌───────────────┐    ┌───────────────────────────┐   │
│  │  1단계         │    │  2단계         │    │  3단계                     │   │
│  │  Pre-training  │───>│  SFT          │───>│  Alignment               │   │
│  │  (사전학습)     │    │  (지도 미세조정) │    │  (정렬)                   │   │
│  └───────┬───────┘    └───────┬───────┘    └─────────┬─────────────────┘   │
│          │                    │                       │                     │
│   수조 토큰의 텍스트     지시-응답 쌍         인간 선호도 데이터          │
│   Common Crawl, Wiki    수만~수십만 개        비교 평가 데이터             │
│   Books, Code                                                              │
│          │                    │                       │                     │
│          ▼                    ▼                       ▼                     │
│   "다음 단어를            "지시를 따르는         "안전하고 유용한            │
│    예측하는 모델"          도우미 모델"            정렬된 모델"              │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │  비용:  ~$100M+          ~$1M-10M             ~$1M-10M              │   │
│  │  기간:  수주~수개월       수일~수주             수일~수주              │   │
│  │  데이터: 수조 토큰       수만~수십만 예시       수만~수십만 비교 쌍     │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

이 장에서는 각 단계를 상세히 분해하고, 여기에 수반되는 데이터 큐레이션, 컴퓨트 예산, 효율적 학습 기법까지 모두 다룬다.

## 1단계: 사전학습 (Pre-training)

### 사전학습이란

사전학습은 LLM 학습에서 가장 비용이 많이 들고, 가장 오래 걸리며, 모델의 "기초 체력"을 결정하는 단계다. 이 단계에서 모델은 인터넷에서 수집한 방대한 텍스트 데이터를 읽으며 언어의 구조, 세계 지식, 논리적 추론 패턴을 습득한다.

비유하자면, 사전학습은 아이가 수년간 책을 읽으며 세상의 지식을 흡수하는 과정과 같다. 아직 특정 질문에 답하는 법을 배운 것은 아니지만, 언어와 지식의 광범위한 기초를 다지는 것이다.

### 학습 데이터셋 (Training Dataset)

사전학습에 사용되는 데이터는 규모가 방대하다. GPT-4 급 모델의 경우 수조(Trillion) 개의 토큰을 학습한다고 알려져 있다.

| 데이터 소스 | 설명 | 특징 |
|-------------|------|------|
| **Common Crawl** | 웹 크롤링으로 수집한 인터넷 텍스트 | 가장 대규모, 하지만 노이즈가 많음 |
| **Wikipedia** | 위키피디아 전체 텍스트 | 고품질 백과사전적 지식 |
| **Books** | 디지털화된 도서 (Books1, Books2, Books3 등) | 깊이 있는 장문 텍스트 |
| **Code** | GitHub 등에서 수집한 소스 코드 | 프로그래밍 능력의 원천 |
| **학술 논문** | ArXiv, PubMed 등 학술 데이터 | 전문 지식과 논리적 추론 |
| **대화 데이터** | Reddit, StackOverflow 등 | 대화 패턴과 Q&A 형식 |

실제 학습 데이터는 이런 소스들을 혼합(mixing)하여 사용한다. 혼합 비율은 모델의 성능에 큰 영향을 미치며, 각 연구소의 노하우에 해당한다. 예를 들어 코드 데이터의 비율을 높이면 코딩 능력이 올라가지만, 다른 능력이 저하될 수 있다.

### 학습 목표: 인과적 언어 모델링 (Causal Language Modeling)

GPT 계열의 디코더 전용(Decoder-Only) 모델은 **인과적 언어 모델링(Causal Language Modeling, CLM)**을 학습 목표로 사용한다. 이는 극도로 단순한 목표다:

> **주어진 앞 문맥을 보고, 다음에 올 토큰을 예측하라.**

```
입력:  "서울의 수도는"
목표:  → 다음 토큰 예측

"서울"   → "의"      (예측 확률 분포에서 학습)
"서울의" → "수도"    (예측 확률 분포에서 학습)
"서울의 수도는" → "한국" (예측 확률 분포에서 학습)
...
```

수학적으로 표현하면 다음과 같다:

```
손실 함수 (Loss Function):

L = -1/T * Σ(t=1 to T) log P(x_t | x_1, x_2, ..., x_{t-1}; θ)

여기서:
- T: 시퀀스의 총 토큰 수
- x_t: t번째 토큰
- θ: 모델의 파라미터
- P(x_t | ...): 모델이 예측한 다음 토큰의 확률
```

이 단순한 목표가 어떻게 "지능"을 만들어내는가? 핵심 통찰은 이렇다: 다음 단어를 정확히 예측하려면 문법, 의미, 논리, 사실 관계, 심지어 추론까지 이해해야 한다.

"대한민국의 수도는 ___이다"를 올바르게 예측하려면 지리적 사실을 알아야 하고, "만약 x > 0이고 y < 0이면, x * y는 ___이다"를 예측하려면 수학적 추론이 필요하다. 수조 개의 이런 예측을 반복하면서 모델은 세상의 지식과 추론 패턴을 파라미터에 압축(compress)한다.

### 분산 학습 (Distributed Training)

GPT-4 급 모델을 학습하려면 수천~수만 개의 GPU가 필요하다. 단일 GPU에는 모델이 들어가지도 않고, 들어가더라도 학습에 수십 년이 걸릴 것이다. 이를 해결하기 위해 여러 가지 분산 학습 기법을 조합하여 사용한다.

#### 데이터 병렬화 (Data Parallelism)

가장 기본적인 분산 학습 방법이다. 모델의 동일한 복사본을 여러 GPU에 배치하고, 학습 데이터를 나누어 각 GPU에서 독립적으로 계산한 후 그래디언트(Gradient)를 합산한다.

```
┌───────────────────────────────────────┐
│          데이터 병렬화                  │
│                                       │
│  GPU 0: 모델 복사본 ← 데이터 배치 0   │
│  GPU 1: 모델 복사본 ← 데이터 배치 1   │
│  GPU 2: 모델 복사본 ← 데이터 배치 2   │
│  GPU 3: 모델 복사본 ← 데이터 배치 3   │
│         │      │      │      │        │
│         └──────┴──────┴──────┘        │
│              그래디언트 합산            │
│              (All-Reduce)             │
└───────────────────────────────────────┘
```

한계: 모델 전체가 각 GPU의 메모리에 올라가야 하므로, 모델 크기가 단일 GPU 메모리를 초과하면 사용할 수 없다.

#### 텐서 병렬화 (Tensor Parallelism)

하나의 레이어를 여러 GPU에 분할한다. 예를 들어, 큰 행렬 곱셈을 여러 GPU에 나누어 동시에 계산한다. Megatron-LM에서 처음 제안된 이 기법은 단일 레이어 내의 연산을 병렬화한다.

```
┌───────────────────────────────────────┐
│          텐서 병렬화                    │
│                                       │
│     하나의 가중치 행렬 W               │
│     ┌────────┬────────┐               │
│     │  W_0   │  W_1   │               │
│     │(GPU 0) │(GPU 1) │               │
│     └────────┴────────┘               │
│                                       │
│  각 GPU가 행렬의 일부를 담당하여        │
│  동시에 계산 후 결과를 합침             │
└───────────────────────────────────────┘
```

장점: 단일 GPU 메모리를 초과하는 큰 레이어도 처리 가능하다. 단점: GPU 간 통신이 빈번하게 발생하여 고속 인터커넥트(NVLink 등)가 필수적이다.

#### 파이프라인 병렬화 (Pipeline Parallelism)

모델의 레이어들을 여러 GPU에 순차적으로 배치한다. 예를 들어 96개 레이어를 가진 모델을 4개 GPU에 나누면, 각 GPU가 24개 레이어를 담당한다.

```
┌───────────────────────────────────────────────────────┐
│          파이프라인 병렬화                               │
│                                                       │
│  GPU 0         GPU 1         GPU 2         GPU 3      │
│  ┌──────┐     ┌──────┐     ┌──────┐     ┌──────┐     │
│  │Layer │     │Layer │     │Layer │     │Layer │     │
│  │ 1-24 │────>│25-48 │────>│49-72 │────>│73-96 │     │
│  └──────┘     └──────┘     └──────┘     └──────┘     │
│                                                       │
│  마이크로 배치(Micro-batch)로 파이프라인 버블 최소화     │
└───────────────────────────────────────────────────────┘
```

문제: 순차적 처리 특성상 "파이프라인 버블(Pipeline Bubble)"이 발생하여 GPU가 유휴 상태가 되는 구간이 생긴다. 이를 줄이기 위해 마이크로 배칭(Micro-batching) 등의 기법을 사용한다.

#### 실제 대규모 학습에서의 조합

실제로는 이 세 가지를 모두 조합하는 **3D 병렬화(3D Parallelism)**를 사용한다. 예를 들어 GPT-3(1750억 파라미터) 학습에서 NVIDIA는 다음과 같은 구성을 사용했다:

- 텐서 병렬화: 8-way (8개 GPU가 하나의 레이어를 분할)
- 파이프라인 병렬화: 8-way (8개 스테이지로 레이어 분배)
- 데이터 병렬화: 64-way (64개의 데이터 병렬 복사본)
- 총 GPU: 8 x 8 x 64 = 4,096개

여기에 ZeRO(Zero Redundancy Optimizer), Gradient Checkpointing, Mixed Precision Training(FP16/BF16) 등의 메모리 최적화 기법까지 더해져 학습이 가능해진다.

## 2단계: 지도 미세조정 (Supervised Fine-Tuning, SFT)

### SFT란 무엇인가

사전학습을 마친 모델은 놀라운 언어 능력을 가지고 있지만, 아직 "도우미"는 아니다. 사전학습된 모델에게 "서울의 인구는?"이라고 물으면, 대답 대신 "서울의 면적은? 서울의 위치는?"처럼 관련 질문을 이어 생성할 수 있다. 왜냐하면 사전학습의 목표는 "다음 토큰 예측"이지 "질문에 답변하기"가 아니기 때문이다.

SFT는 이 "원시(raw) LLM"을 **대화형 도우미**로 변환하는 단계다. 고품질의 (지시, 응답) 쌍을 사용하여 모델이 지시를 따르는 방법을 학습시킨다.

### 지시 따르기 데이터셋 (Instruction Following Dataset)

SFT에 사용되는 데이터는 사전학습 데이터와 근본적으로 다르다. 형식은 다음과 같다:

```json
{
  "instruction": "Python으로 피보나치 수열의 n번째 항을 구하는 함수를 작성해주세요.",
  "input": "",
  "output": "def fibonacci(n):\n    if n <= 0:\n        return 0\n    elif n == 1:\n        return 1\n    else:\n        a, b = 0, 1\n        for _ in range(2, n + 1):\n            a, b = b, a + b\n        return b\n\n# 사용 예시\nprint(fibonacci(10))  # 55"
}
```

데이터셋의 출처는 크게 두 가지다:

1. **인간이 직접 작성**: 전문 어노테이터(Annotator)가 다양한 지시를 작성하고 이에 대한 이상적인 응답을 작성한다. 비용이 높지만 품질이 우수하다. OpenAI의 InstructGPT 논문에서는 약 40명의 계약자가 이 작업을 수행했다.

2. **AI 지원 생성**: 기존 LLM을 활용하여 지시-응답 쌍을 대량 생성한 후, 인간이 품질을 검수한다. Self-Instruct, Alpaca 방법론이 대표적이다.

주요 SFT 데이터셋의 예:

| 데이터셋 | 규모 | 특징 |
|----------|------|------|
| OpenAssistant | ~160K 대화 | 커뮤니티 제작, 다국어 지원 |
| Dolly | ~15K | Databricks 직원이 직접 작성 |
| FLAN Collection | 수백만 | Google의 다양한 NLP 태스크 모음 |
| ShareGPT | ~70K | 실제 ChatGPT 대화 수집 |
| WizardLM | ~250K | Evol-Instruct로 난이도 점진적 증가 |

### 원시 LLM이 도우미가 되는 과정

SFT 전후의 차이를 비교해보자:

```
[SFT 전 - 사전학습만 된 모델]
사용자: "이메일 작성을 도와줘."
모델:   "이메일 작성을 도와줘라고 부탁하는 것은 일상적인 요청 중 하나이다.
         이메일은 업무 커뮤니케이션의 핵심 수단으로..." (백과사전처럼 서술)

[SFT 후 - 미세조정된 모델]
사용자: "이메일 작성을 도와줘."
모델:   "네, 이메일 작성을 도와드리겠습니다! 다음 내용을 알려주세요:
         1. 받는 사람은 누구인가요?
         2. 어떤 목적의 이메일인가요?
         3. 어떤 톤(격식/비격식)을 원하시나요?"
```

SFT는 모델의 기존 지식을 파괴하지 않으면서 "응답 스타일"과 "지시 따르기 능력"을 입히는 것이다. 비교적 적은 양의 고품질 데이터(수만~수십만 개)로도 극적인 변화를 만들어낸다. 이것이 가능한 이유는 사전학습 단계에서 이미 모든 지식과 능력을 갖추었고, SFT는 단지 그 능력을 "올바른 형식으로 출력하는 방법"을 가르치기 때문이다.

## 3단계: 정렬 (Alignment)

### 왜 정렬이 필요한가

SFT만으로도 꽤 유용한 모델이 만들어지지만, 여전히 문제가 남아 있다:

- 유해하거나 편향된 응답을 생성할 수 있다
- 확신 없는 내용도 자신 있게 답변한다 (환각)
- 사용자의 의도를 미묘하게 벗어나는 경우가 있다
- 윤리적으로 문제가 있는 요청에도 순순히 응하는 경우가 있다

정렬(Alignment) 단계는 모델을 **안전하고(safe), 유용하며(helpful), 정직한(honest)** 방향으로 조정하는 것이다.

### RLHF (Reinforcement Learning from Human Feedback)

RLHF는 OpenAI의 InstructGPT 논문(2022)에서 대중화된 정렬 기법으로, ChatGPT의 핵심 기술이다. 세 단계로 구성된다.

#### Step 1: 인간 선호도 수집 (Collect Human Preferences)

동일한 프롬프트에 대해 모델이 여러 응답을 생성하면, 인간 어노테이터가 어떤 응답이 더 나은지 순위를 매긴다.

```
프롬프트: "양자 컴퓨팅을 5살 아이에게 설명해줘"

응답 A: "양자 컴퓨터는 큐비트(Qubit)를 사용하여 중첩과 얽힘 상태를
         활용한 계산 장치입니다..." (너무 어려움)

응답 B: "일반 컴퓨터는 동전의 앞면 아니면 뒷면만 볼 수 있어.
         그런데 양자 컴퓨터는 동전이 빙글빙글 돌고 있는 동안에도
         볼 수 있는 마법 같은 컴퓨터야!" (적절한 수준)

응답 C: "양자역학의 기본 원리에 따르면..." (완전히 부적절)

인간 평가: B > A > C
```

이런 비교 데이터를 수만~수십만 쌍 수집한다.

#### Step 2: 보상 모델 학습 (Train Reward Model)

수집된 선호도 데이터로 **보상 모델(Reward Model)**을 학습시킨다. 보상 모델은 주어진 (프롬프트, 응답) 쌍을 입력받아 "이 응답이 얼마나 좋은가"를 점수로 출력하는 모델이다.

```
보상 모델의 학습 목표:

Loss = -log(σ(r(x, y_w) - r(x, y_l)))

여기서:
- x: 프롬프트
- y_w: 인간이 선호한 응답 (winner)
- y_l: 인간이 비선호한 응답 (loser)
- r(x, y): 보상 모델이 출력한 점수
- σ: 시그모이드 함수

→ 선호 응답에 더 높은 점수를, 비선호 응답에 더 낮은 점수를 부여하도록 학습
```

보상 모델은 보통 SFT 모델과 동일한 아키텍처에서 마지막 레이어만 스칼라 출력으로 교체한 형태다.

#### Step 3: PPO로 정책 최적화 (Optimize Policy with PPO)

학습된 보상 모델을 사용하여 LLM(정책, Policy)을 강화학습으로 최적화한다. 여기서 사용되는 알고리즘이 **PPO(Proximal Policy Optimization)**다.

```
PPO 기반 RLHF 최적화 루프:

┌─────────────────────────────────────────────────────┐
│                                                     │
│  1. LLM(정책 모델)이 프롬프트에 대한 응답 생성        │
│                    │                                │
│                    ▼                                │
│  2. 보상 모델이 응답에 점수 부여                      │
│                    │                                │
│                    ▼                                │
│  3. PPO 알고리즘으로 정책 모델 업데이트               │
│     - 보상을 높이는 방향으로 파라미터 조정             │
│     - KL 페널티로 원래 모델에서 너무 벗어나지 않도록   │
│                    │                                │
│                    ▼                                │
│  4. 1번으로 돌아가 반복                               │
│                                                     │
└─────────────────────────────────────────────────────┘

최적화 목표:
maximize E[r(x, y)] - β * KL(π_θ || π_ref)

- r(x, y): 보상 모델의 점수
- KL(...): 현재 정책과 참조 정책(SFT 모델) 사이의 KL 발산
- β: KL 페널티 계수 (너무 급격한 변화 방지)
```

**KL 페널티**가 중요한 이유: 보상만 최대화하면 모델이 보상 모델을 "속이는" 방법(Reward Hacking)을 학습할 수 있다. KL 페널티는 SFT 모델에서 크게 벗어나지 않도록 제약을 건다.

RLHF의 핵심 한계:
- 보상 모델 학습 자체가 불완전할 수 있다
- PPO 학습이 불안정하고 하이퍼파라미터에 민감하다
- 전체 파이프라인이 복잡하다 (모델 3개 필요: SFT 모델, 보상 모델, 정책 모델)

### DPO (Direct Preference Optimization) - RLHF의 간소화된 대안

2023년에 발표된 DPO는 RLHF의 복잡성을 크게 줄인 기법이다. 핵심 아이디어는 **보상 모델을 별도로 학습하지 않고, 선호도 데이터에서 직접 정책을 최적화**하는 것이다.

```
RLHF vs DPO 파이프라인 비교:

RLHF:
  선호도 데이터 → 보상 모델 학습 → PPO로 정책 최적화 (3단계)

DPO:
  선호도 데이터 → 직접 정책 최적화 (1단계)
```

DPO의 손실 함수:

```
L_DPO = -E[log σ(β * (log π_θ(y_w|x)/π_ref(y_w|x) - log π_θ(y_l|x)/π_ref(y_l|x)))]

여기서:
- π_θ: 현재 학습 중인 정책
- π_ref: 참조 정책 (SFT 모델)
- y_w, y_l: 선호/비선호 응답
- β: 온도 파라미터
```

DPO의 장점:
- 보상 모델을 별도로 학습할 필요가 없다
- PPO 같은 불안정한 강화학습이 필요 없다
- 구현이 간단하여 일반 지도학습처럼 학습할 수 있다
- 메모리 효율적이다 (모델 2개만 필요: 학습 모델, 참조 모델)

DPO는 LLaMA 2, Zephyr 등 여러 오픈소스 모델에서 성공적으로 적용되었으며, RLHF 대비 동등하거나 더 나은 성능을 보이는 경우가 많다.

### Constitutional AI - Anthropic의 접근법

Claude가 다른 모델과 차별화되는 핵심 기술이 바로 **Constitutional AI(CAI)**이다. Anthropic이 2022년에 발표한 이 방법은 기존 RLHF의 근본적 한계를 다른 방식으로 해결한다.

#### RLHF의 문제점

기존 RLHF는 인간 어노테이터에게 전적으로 의존한다:
- 어노테이터마다 기준이 다르다
- 미묘한 안전성 문제를 일관되게 평가하기 어렵다
- 수만 건의 평가에 막대한 비용이 들며, 확장(Scale)에 한계가 있다

#### CAI의 핵심: 원칙(Constitution) 기반 자기 개선

CAI는 명시적 원칙(Constitution)을 모델에게 제시하고, 모델 스스로 자신의 응답을 평가하고 개선하게 한다.

```
Constitutional AI의 두 단계:

[1단계: 자기 비평과 수정 (Self-Critique and Revision)]

원칙 예시:
- "응답이 유해하거나 비윤리적인 내용을 포함하지 않는지 확인하라"
- "사용자를 속이는 정보를 제공하지 않는지 확인하라"
- "요청이 위험한 경우, 왜 도움을 줄 수 없는지 정중하게 설명하라"

프로세스:
  사용자 요청 → 모델이 초기 응답 생성
                    │
                    ▼
              원칙에 비추어 자기 비평
              "이 응답이 원칙 X를 위반하는가?"
                    │
                    ▼
              위반 시 응답을 수정하여 새로운 버전 생성
                    │
                    ▼
              수정된 응답으로 SFT 데이터 구축

[2단계: RLAIF (RL from AI Feedback)]

  수정 전/후 응답 쌍을 비교 데이터로 사용
  → AI 피드백 기반 보상 모델 학습
  → 강화학습으로 정책 최적화
```

#### Claude가 이러한 방식인 이유

Constitutional AI 덕분에 Claude는:

1. **일관된 원칙**: 인간 어노테이터 개인의 판단이 아닌, 명시된 원칙에 따라 행동한다
2. **확장 가능한 안전성**: 인간 평가 없이도 AI 피드백으로 안전성을 지속적으로 개선할 수 있다
3. **투명한 거절**: 위험한 요청을 거절할 때, 왜 거절하는지 설명할 수 있다
4. **무해함과 유용함의 균형**: 지나치게 거절하지도, 무분별하게 응하지도 않는 균형을 추구한다

이것이 Claude가 때때로 요청을 정중히 거절하면서도 대안을 제시하려 하는 이유이며, "도움이 되고, 무해하며, 정직한(Helpful, Harmless, Honest: HHH)" 모델을 목표로 하는 Anthropic의 철학이 반영된 결과다.

## 데이터 큐레이션 (Data Curation)

### 데이터 품질이 모든 것을 결정한다

"Garbage In, Garbage Out"은 LLM 학습에서 가장 중요한 원칙이다. 아무리 좋은 아키텍처와 많은 컴퓨트를 투입해도 데이터의 품질이 나쁘면 모델의 성능은 기대에 미치지 못한다.

### 중복 제거 (Deduplication)

웹에서 수집한 데이터에는 엄청난 양의 중복이 존재한다. 동일한 뉴스 기사가 수백 개 사이트에 복사되어 있고, 보일러플레이트(Boilerplate) 텍스트가 무수히 반복된다.

중복 제거 기법:
- **정확 중복 제거 (Exact Dedup)**: 해시 기반으로 완전히 동일한 문서 제거
- **근사 중복 제거 (Near Dedup)**: MinHash, SimHash 등으로 유사한 문서 제거
- **n-gram 중복 제거**: 반복되는 n-gram 패턴 제거

연구에 따르면, 중복 제거만으로도 모델 성능이 유의미하게 향상된다. 중복된 데이터는 모델이 특정 패턴을 과도하게 암기하게 만들어 일반화 능력을 떨어뜨리기 때문이다.

### 필터링 (Filtering)

수집된 원시 데이터에서 학습에 부적합한 내용을 제거하는 과정이다:

- **언어 필터링**: 목표 언어가 아닌 텍스트 제거 (fastText 등의 언어 분류기 활용)
- **품질 필터링**: 낮은 품질의 텍스트 제거
  - 퍼플렉시티(Perplexity) 기반 필터: 기존 언어 모델로 평가하여 비정상적 텍스트 제거
  - 휴리스틱 필터: 특수 문자 비율, 단어 반복률, 문장 길이 등으로 필터링
- **개인정보 제거**: 이메일, 전화번호, 주민등록번호 등 PII(Personally Identifiable Information) 제거

### 유해 콘텐츠 제거 (Toxicity Removal)

인터넷 텍스트에는 혐오 표현, 성적 콘텐츠, 폭력적 내용 등이 포함되어 있다. 이를 제거하지 않으면 모델이 유해한 출력을 생성할 확률이 높아진다.

- **분류기 기반 필터링**: 유해 콘텐츠 분류 모델(Perspective API 등)을 사용하여 점수를 매기고, 임계값 이상을 제거
- **키워드 기반 필터링**: 알려진 유해 단어/구문 목록을 사용한 필터링
- **주의점**: 너무 공격적으로 필터링하면 특정 집단(소수자 관련 텍스트 등)의 데이터가 과도하게 제거되어 편향이 발생할 수 있다

### 데이터 혼합 비율 (Data Mixing)

서로 다른 도메인의 데이터를 어떤 비율로 혼합하느냐도 성능에 큰 영향을 미친다:

```
데이터 혼합 예시 (가상):

┌─────────────────────────────────────┐
│  웹 텍스트 (Common Crawl)    60%    │ ████████████████████████
│  도서 (Books)               15%    │ ██████
│  코드 (Code)                10%    │ ████
│  위키피디아 (Wikipedia)       5%    │ ██
│  학술 논문 (Academic)         5%    │ ██
│  대화 데이터 (Conversation)    5%    │ ██
└─────────────────────────────────────┘
```

각 도메인의 비율을 조정하면 모델의 강점이 달라진다. 코드 비율을 높이면 코딩 능력이 향상되고, 학술 논문 비율을 높이면 전문 지식이 강화되지만, 항상 트레이드오프가 존재한다.

## 컴퓨트 예산과 학습 비용 (Compute Budget and Training Costs)

### LLM 학습에는 얼마나 드는가

LLM 학습의 비용은 크게 세 가지 요소로 결정된다:

1. **GPU/TPU 하드웨어 비용**: 가장 큰 비중
2. **전력 비용**: 수천 GPU를 수개월 운용하면 전기료만 수백만 달러
3. **인프라 비용**: 네트워킹, 냉각, 스토리지 등

### 주요 모델의 추정 학습 비용

| 모델 | 파라미터 수 | 추정 학습 비용 | 추정 GPU 사용량 |
|------|-------------|---------------|-----------------|
| GPT-3 (2020) | 175B | ~$5M | ~3,640 PFLOP/s-days |
| LLaMA 2 70B (2023) | 70B | ~$2-3M | 1,720,320 GPU-hours (A100) |
| GPT-4 (2023) | 비공개 (추정 1.8T MoE) | ~$60-100M+ | 수만 개 A100, 수개월 |
| LLaMA 3 405B (2024) | 405B | ~$60-100M+ | 30,840,000 GPU-hours (H100) |
| Claude 3.5 Sonnet (2024) | 비공개 | 비공개 (수천만 달러 추정) | 비공개 |

> 주의: 위 비용은 공개된 정보와 업계 추정치를 기반으로 한 것이며, 실제 비용은 다를 수 있다.

### 비용 구성 상세

GPT-4 급 모델 학습 비용의 대략적 내역(추정):

```
총 추정 비용: ~$100M

┌─────────────────────────────────────────────┐
│  GPU 임대/감가 비용          ~70-80%         │
│  (H100 x 25,000개 x 90일)                   │
│                                             │
│  전력 비용                   ~10-15%         │
│  (25,000 GPU x 700W x 90일)                 │
│                                             │
│  인프라/네트워킹             ~5-10%          │
│  (InfiniBand, 스토리지 등)                   │
│                                             │
│  인건비 (연구원, 엔지니어)    ~3-5%          │
│                                             │
│  데이터 수집/처리             ~2-3%          │
└─────────────────────────────────────────────┘
```

### FLOP으로 보는 학습 연산량

학습 비용을 하드웨어 독립적으로 측정할 때 **FLOP(부동소수점 연산 횟수)**을 사용한다.

Transformer 모델의 학습에 필요한 대략적 FLOP:

```
Training FLOP ≈ 6 * N * D

여기서:
- N: 모델의 파라미터 수
- D: 학습 토큰 수
- 6: 순전파(2) + 역전파(4)의 계수

예시:
- GPT-3 (175B 파라미터, 300B 토큰): 6 * 175B * 300B = 3.15 x 10^23 FLOP
- LLaMA 2 70B (70B 파라미터, 2T 토큰):  6 * 70B * 2T = 8.4 x 10^23 FLOP
```

## Chinchilla 스케일링 (Chinchilla Scaling)

### 배경: 모델이 크면 무조건 좋은가?

GPT-3 이후 업계의 트렌드는 "모델을 더 크게 만들면 더 좋아진다"였다. 하지만 2022년 DeepMind가 발표한 **Chinchilla 논문**은 이 가정에 의문을 던졌다.

### Chinchilla의 핵심 발견

연구진은 동일한 컴퓨트 예산에서 모델 크기(N)와 학습 데이터 양(D)의 최적 비율을 조사했다. 결론은:

> **모델 파라미터 수와 학습 토큰 수를 거의 동일한 비율로 늘려야 최적이다.**

구체적으로:

```
Chinchilla 최적 스케일링 법칙:

모델 크기 N에 대한 최적 학습 토큰 수 D:
D ≈ 20 * N

즉, 1B 파라미터 모델은 약 20B 토큰으로 학습해야 최적
    70B 파라미터 모델은 약 1.4T 토큰으로 학습해야 최적
   200B 파라미터 모델은 약 4T 토큰으로 학습해야 최적
```

### Chinchilla가 바꾼 것

이 발견이 왜 중요했는가:

| 기존 접근 (GPT-3 시대) | Chinchilla 이후 |
|------------------------|-----------------|
| 모델을 크게 만드는 데 집중 | 데이터 양도 동등하게 중요 |
| 175B 파라미터 + 300B 토큰 | 70B 파라미터 + 1.4T 토큰이 더 효율적 |
| "파라미터 수가 곧 실력" | "최적 비율이 중요" |
| 학습 데이터를 1 에포크만 통과 | 데이터를 충분히 활용 |

실제로 Chinchilla(70B 파라미터, 1.4T 토큰)는 Gopher(280B 파라미터, 300B 토큰)보다 4배 작으면서도 거의 모든 벤치마크에서 더 좋은 성능을 보여주었다.

이후 LLaMA 시리즈는 Chinchilla의 교훈을 적극 반영하여, 상대적으로 작은 모델(7B, 13B, 65B)을 더 많은 데이터(1-2T 토큰)로 학습하는 전략을 취했다. LLaMA 3에서는 이 비율을 훨씬 넘어 405B 파라미터에 15T 이상의 토큰을 사용하여, 추론 시 효율성을 극대화하는 "과도학습(Over-training)" 전략을 채택하기도 했다.

## LoRA와 파라미터 효율적 미세조정 (PEFT)

### 문제: 전체 파라미터 미세조정은 너무 비싸다

GPT-4 급 모델을 특정 도메인에 맞게 미세조정하려면 원칙적으로 모든 파라미터를 업데이트해야 한다. 하지만:

- 수천억 파라미터를 모두 학습하려면 거대한 GPU 클러스터가 필요하다
- 미세조정된 모델의 전체 가중치를 저장하면 수백 GB의 스토리지가 필요하다
- 여러 용도의 미세조정 모델을 유지하면 비용이 기하급수적으로 증가한다

### PEFT (Parameter-Efficient Fine-Tuning)란

PEFT는 **전체 파라미터의 극히 일부만 학습하면서도 전체 미세조정에 근접한 성능을 달성**하는 기법들의 총칭이다.

### LoRA (Low-Rank Adaptation)

2021년 Microsoft가 발표한 LoRA는 가장 널리 사용되는 PEFT 기법이다. 핵심 아이디어는 놀라울 정도로 우아하다:

> **가중치 업데이트 행렬(Delta W)은 실제로 저랭크(Low-Rank)이므로, 두 개의 작은 행렬로 분해할 수 있다.**

```
기존 미세조정:
  W' = W + ΔW        (W: 원래 가중치, ΔW: 업데이트, 크기 동일)

LoRA:
  W' = W + B × A     (B: d×r 행렬, A: r×d 행렬, r << d)

여기서:
- d: 원래 가중치 행렬의 차원 (예: 4096)
- r: 랭크 (예: 8, 16, 32)
- 원래 파라미터 수: d × d = 4096 × 4096 = 16,777,216
- LoRA 파라미터 수: d × r + r × d = 4096 × 16 + 16 × 4096 = 131,072
- 비율: 131,072 / 16,777,216 ≈ 0.78% (약 128배 절감!)
```

시각적으로 표현하면:

```
┌────────────────────────────────────────────────────┐
│               LoRA의 구조                           │
│                                                    │
│  입력 x ─────────────┐                             │
│        │              │                             │
│        ▼              ▼                             │
│   ┌─────────┐   ┌──────────┐                       │
│   │  원래    │   │  LoRA    │                       │
│   │  가중치  │   │  어댑터   │                       │
│   │  W       │   │          │                       │
│   │ (동결)   │   │ ┌──┐┌──┐│                       │
│   │          │   │ │A ││B ││                       │
│   │ d × d    │   │ │r ││d ││                       │
│   │          │   │ │× ││× ││                       │
│   │          │   │ │d ││r ││                       │
│   └────┬─────┘   │ └──┘└──┘│                       │
│        │         └────┬─────┘                       │
│        │              │                             │
│        ▼              ▼                             │
│       h = Wx    +   BAx                             │
│                                                    │
│   원래 가중치는 동결(Freeze)되고,                    │
│   작은 행렬 A, B만 학습한다                          │
└────────────────────────────────────────────────────┘
```

### LoRA의 실용적 장점

1. **메모리 절감**: 전체 미세조정 대비 GPU 메모리 사용량이 크게 감소한다
2. **빠른 학습**: 학습할 파라미터가 적으므로 학습이 빠르다
3. **저장 효율**: LoRA 어댑터는 수 MB~수십 MB에 불과하여, 용도별 어댑터를 여러 개 유지해도 부담이 없다
4. **교체 용이**: 원래 모델에 다른 LoRA 어댑터를 끼워넣기만 하면 용도를 전환할 수 있다

### QLoRA - 더 극단적인 효율화

QLoRA(Quantized LoRA)는 기본 모델을 4비트로 양자화한 상태에서 LoRA를 적용하는 기법이다. 이를 통해 65B 파라미터 모델도 단일 48GB GPU(A6000 등)에서 미세조정할 수 있다.

```
QLoRA의 메모리 효율:

65B 모델 전체 미세조정:     ~780 GB (GPU 메모리)
65B 모델 LoRA:             ~200 GB
65B 모델 QLoRA (4-bit):    ~33 GB    ← 단일 GPU로 가능!
```

### 기타 PEFT 기법들

| 기법 | 핵심 아이디어 | 학습 파라미터 비율 |
|------|-------------|-------------------|
| **LoRA** | 가중치 업데이트를 저랭크 행렬로 분해 | ~0.1-1% |
| **QLoRA** | 4-bit 양자화 + LoRA | ~0.1-1% |
| **Prefix Tuning** | 입력 앞에 학습 가능한 가상 토큰 추가 | ~0.1% |
| **Prompt Tuning** | 소프트 프롬프트(연속 벡터)를 학습 | ~0.01% |
| **Adapter Layers** | 트랜스포머 레이어 사이에 작은 어댑터 삽입 | ~1-5% |
| **IA3** | 활성값에 학습 가능한 벡터를 곱함 | ~0.01% |

## 파국적 망각 (Catastrophic Forgetting)

### 문제 정의

**파국적 망각(Catastrophic Forgetting)**은 신경망이 새로운 작업을 학습할 때 이전에 학습한 지식을 급격히 잃어버리는 현상이다. 이는 LLM에서 특히 심각한 문제가 된다.

```
파국적 망각의 예시:

[미세조정 전]
Q: "프랑스의 수도는?"  → "파리입니다"  ✓
Q: "Python list 정렬?"  → "sorted() 또는 .sort()를 사용합니다"  ✓

[의료 도메인 미세조정 후]
Q: "당뇨병 증상은?"    → "다음, 다뇨, 다식이 대표 증상입니다"  ✓ (새로 학습)
Q: "프랑스의 수도는?"  → "파리... 증후군은 여행자가..."  ✗ (기존 지식 손상)
Q: "Python list 정렬?"  → (품질 저하된 응답)  ✗ (기존 능력 상실)
```

### 왜 발생하는가

신경망의 파라미터는 모든 작업에 공유된다. 새로운 데이터로 학습하면 기존 데이터에 대한 최적 가중치가 변경되며, 이전 지식이 "덮어써진다."

### 완화 전략

#### 1. 학습률 조절 (Learning Rate Control)

미세조정 시 매우 작은 학습률을 사용하여, 사전학습된 가중치가 크게 변하지 않도록 한다.

```
사전학습 학습률:   ~1e-4 ~ 3e-4
SFT 학습률:       ~1e-5 ~ 5e-5   (10배 이상 작음)
LoRA 학습률:      ~1e-4 ~ 3e-4   (LoRA 파라미터만 변경되므로 상대적으로 높아도 안전)
```

#### 2. 데이터 혼합 (Data Mixing / Replay)

미세조정 데이터에 사전학습 데이터의 일부를 섞어 함께 학습시킨다. 이를 통해 기존 지식이 유지된다.

```
미세조정 데이터 구성 예시:
- 새로운 도메인 데이터: 70%
- 기존 사전학습 데이터 샘플: 20%
- 일반 지시 따르기 데이터: 10%
```

#### 3. LoRA/PEFT 활용

LoRA를 사용하면 원래 가중치를 완전히 동결(Freeze)하고, 추가된 소규모 파라미터만 학습하므로 파국적 망각을 구조적으로 방지할 수 있다. 새로운 도메인에 적응하면서도 원래 능력은 보존된다.

#### 4. 정규화 (Regularization)

EWC(Elastic Weight Consolidation) 등의 기법으로, 이전 작업에 중요한 파라미터가 크게 변하지 않도록 제약을 건다.

```
EWC 손실 함수:
L_total = L_new + λ * Σ F_i * (θ_i - θ*_i)^2

여기서:
- L_new: 새로운 작업의 손실
- F_i: Fisher 정보 행렬 (파라미터의 중요도)
- θ*_i: 이전 작업 학습 후의 파라미터 값
- λ: 정규화 강도
```

#### 5. 모델 병합 (Model Merging)

최근에는 서로 다른 작업으로 미세조정된 여러 모델의 가중치를 산술적으로 병합하는 기법도 연구되고 있다:

- **Linear Merging**: 두 모델의 가중치를 가중 평균
- **TIES Merging**: 불필요한 변화를 제거한 후 병합
- **DARE**: 무작위로 일부 가중치 변화를 제거한 후 병합

| **LoRA/PEFT** | 전체 파라미터의 0.1-1%만 학습하여 효율적 미세조정 |
| **Catastrophic Forgetting** | 새 학습 시 기존 지식 상실. LoRA, 데이터 혼합 등으로 완화 |
